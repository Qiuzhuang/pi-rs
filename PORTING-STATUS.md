# Porting status

Tracks what is ported and what is outstanding. Update when finishing a module.

| Area | Status |
|------|--------|
| workspace skeleton | done |
| pi-ai: core types (`types.ts`, `model-schema.ts`, `compat-schema.ts` incl. generated JSON Schemas in `data/schemas.json`), event stream, identity, diagnostics | done. Notes: `Api`/`ProviderId` are `String`; one `StreamOptions` struct covers `ProviderRequestOptions`/`StreamOptions`/`SimpleStreamOptions`, API-specific options (e.g. `thinkingEnabled`, `effort`, `reasoningEffort`, `toolChoice`, `azure*`) go in `StreamOptions.extra` under their TS names; the TS `fetch` option is `http_client: reqwest::Client`; `AbortSignal` is `CancellationToken`; compat is one superset struct `ModelCompat` (per-API names are aliases); unknown model/compat keys are preserved via `extra` |
| pi-ai: utils (json-parse + partial-json, transcript, text, overflow, retry, provider-retry, error-body, headers, estimate, provider-env, models-error, model-operations, identity, oauth-page, node-http-proxy, sanitize-unicode, hash, uuid, sleep, abort, typebox-helpers, validation, SSE decoder, HTTP client) | done. Notes: tool argument validation is a built-in JSON Schema validator with TypeBox's English messages; every schema takes the plain-JSON-schema coercion path of `validation.ts` (TypeBox `Value.Convert` only applies to TypeBox-built schemas in TS). `sanitize_surrogates` is the identity (Rust strings cannot hold lone surrogates) |
| pi-ai: models (`Provider` trait, `create_provider`, `Models` collection with auth/refresh/login/logout/stream/complete/deferred/images/classify, `calculate_cost`, thinking levels), models-store, auth (types, credential store, helpers, resolve, context, OAuth flow registry `auth::oauth_load`), env-api-keys, model catalog (`models_generated`, embedded `data/*.json` from @earendil-works/pi-ai@1.3.0), all built-in provider definitions, compat global API (`compat::stream/complete/register_api_provider/register_faux_provider`), legacy aliases, image-models, session-resources, faux provider, api/lazy, simple-options, transform-messages, constrained-sampling, github-copilot headers, azure config, anthropic-messages and openai-completions over HTTP+SSE | done. Notes: telemetry observation (`telemetry.ts`, `observeModelRequest`) is not wired; Anthropic workload identity federation (SDK OIDC token exchange) errors with "not supported in this build"; per-provider OAuth flows (`auth/oauth/*`) are not ported: providers advertise OAuth via `lazy_builtin_oauth` and fail until a flow is registered with `auth::oauth_load::register_oauth_flow_loader`. APIs without an implementation (google, vertex, mistral, bedrock, codex at time of writing) produce a stream error; add one by adding `api/<name>.rs` and a match arm in `api::registry::resolve_builtin_api` (or `register_builtin_api_implementation`) |
| pi-tui: core utils (width/wrap/truncate/slice), colors, oklab, terminal-colors, keys, stdin-buffer, keybindings, kill-ring, undo-stack, word-navigation, fuzzy | done |
| pi-telemetry: contracts, noop, in-memory recorder/store, metrics, schemas, typed starters, render, conformance suite (all TS tests ported) | done. Notes: TS compile-time schema typing (exact attribute types) has no Rust equivalent; `TypedSpanStarter`/`TypedTelemetryMetrics` bind schemas at runtime without validation, as in TS. Callbacks are futures: `start_span`/`try_start_span` (an `Err` sets error status); dropping an unfinished span future settles it with an `AbortError` status. Clocks are injectable (`ManualTelemetryClock`) instead of mocking `Date.now` |
| pi-mcp: jsonrpc/types/content, client (handshake, paginated tools/resources/templates, read, call, progress, timeouts, cancellation, server requests, list_changed), stdio (process groups, SIGTERM/SIGKILL shutdown, exit hook), streamable HTTP (JSON/SSE, sessions, GET stream, resumption, reconnect, auth retry), in-memory, auth provider, OAuth (discovery, PKCE, DCR, CIMD, refresh, step-up, provider/store, callback server); all TS tests ported | done. Notes: errors are one cloneable `pi_mcp::Error` enum (`name()` gives the TS class); `AbortSignal` wraps `CancellationToken` and keeps the reason; `McpFetch` is a closure over `HttpRequest`/`HttpResponse` (reqwest default); request methods dispatch when called and dropping the returned future cancels the request. Rust additions: `list_prompts`/`get_prompt`. Windows cross-spawn shim handling (`.cmd` via cmd.exe, PATHEXT) is implemented but untested here. Stdio test fixtures are POSIX sh scripts |
| pi-agent: types, agent-loop, agent, proxy, stream-fn; all TS tests ported (agent-loop, agent, proxy, e2e via faux provider) | done. Notes: custom messages are `AgentMessage::Custom` (raw JSON fields); in-place `args` mutation in `beforeToolCall` is `BeforeToolCallResult.args`; `Agent.continue()` is `continue_run()` |
